هذه الوحدة اختيارية، لكنها الأقرب لبيئة العمل الحقيقية في البرنامج كله.

المشكلة التي يحلّها الفحص الآلي

الوحدة 06 — الأتمتة الاحترافية (اختيارية) · 3/18
  • أمس: كان المراجع البشري هو خط الدفاع الوحيد
  • المراجع يسهو، والوقت قصير، والملفات كثيرة
  • الحل: مراجع آلي صبور لا يمل، يفحص كل طلب سحب بنفس المعايير
  • لكن الفحص الآلي لا يغني عن المراجعة البشرية — بل يحرّرها للتفكير

الفحص الآلي يقدّم حكماً (نجاح/فشل)، وحماية الفرع تفرض قواعد وصول. كلاهما ضروري، ولا أحدهما بديل عن الآخر.

المهمة 1 — ملف سير العمل (validate.yml)

الوحدة 06 — الأتمتة الاحترافية (اختيارية) · 5/18
# .github/workflows/validate.yml
name: validate
on:
  pull_request:
    branches: [ main ]
  push:
    branches: [ main ]
concurrency:
  group: validate-${{ github.ref }}
  cancel-in-progress: true
jobs:
  checks:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: node tools/build-index.mjs
      - run: node tests/validate-members.mjs
      - run: git diff --exit-code -- data/members-index.json data/members-bundle.js

المهمة 1 — اقرأه واسأل الأسئلة الأربعة

الوحدة 06 — الأتمتة الاحترافية (اختيارية) · 6/18
  • متى يعمل؟ (عند كل طلب سحب نحو main، وعند كل دفع إلى main)
  • أين يعمل؟ (على خادم GitHub في بيئة نظيفة ubuntu-latest، لا على جهازك)
  • ما الخطوات الثلاث؟ (توليد الفهرس ← فحص البطاقات ← مطابقة الملفات المولَّدة)
  • لماذا concurrency مع cancel-in-progress؟ (ليلغي الفحص القديم عند دفعة جديدة، فلا ننتظر نتائج قديمة)

سؤال حاسم: ماذا تكشف الخطوة الأخيرة git diff --exit-code؟ ← نسيان إعادة توليد الفهرس بعد إضافة بطاقة — أشهر خطأ في هذا المشروع.

المهمة 3 — شبكة إضافية: التحقق الضعيف يكذب

الوحدة 06 — الأتمتة الاحترافية (اختيارية) · 9/18
# الفحص القديم (غير دقيق):
$ grep -rInE "^(<<<<<<<|>>>>>>>|=======)$" --exclude-dir=.git .
 
# ثلاث ثغرات، جرّبها على فرع تجريبي:
#  1) نطاق محدود بامتدادات → تجاهل sandbox/team-slogan.txt  ← الأخطر
#  2) يشترط العلامة وحدها في السطر؛ والحقيقية <<<<<<< HEAD
#  3) إيجابيات كاذبة على سطر ======= فاصل في التوثيق بعلامات دمج

لذلك المهمة الأخيرة في سجل التغييرات تكتب الفحص الصحيح:

grep -rInE "^(<{7}|={7}|>{7})( |$)" --exclude-dir=.git .

  • من يكتشف ضعف الفحص القديم ويوثّقه يحصل على 5 درجات إضافية

فكرة الاحتراف — تجربة الفرق

الوحدة 06 — الأتمتة الاحترافية (اختيارية) · 17/18
  • «أجرتنا تعلّم كلاماً، وهذه الوحدة أظهرت لي ما يحدث فعلاً عند كل دفع.»
  • «رأيت أول مرة فحصاً يفشل بسبب ملف لم أُولّده — درس لا يُنسى.»
  • «صفحة الإصدار على GitHub تجعل مشروعنا يبدو حقيقياً.»
  • سؤال الحماية: ما الفرق بين «فحص مطلوب» و«حماية الفرع»؟
  • الجواب: الفحص يعطي حكماً على الجودة؛ الحماية تفرض قواعد الوصول والدمج.
  • سؤال الإصدار: ما الذي يجعل الإصدار رسمياً؟
  • الجواب: وسم معنون مرفوع + ملفات نهائية + سجل تغييرات.

إتقان الأربعة — CI + الحماية + CODEOWNERS + الإصدار — هو الفرق بين «أعرف Git» و«جاهز للعمل في فريق هندسي».

ختام الوحدة والمشروع

الوحدة 06 — الأتمتة الاحترافية (اختيارية) · 18/18
  • المشروع الآن: فحص آلي يحمي الجودة، قواعد تحمي الفرع، وإصدار موثّق يحمل رقمه
  • هذا ملف أعمال حقيقي يمكنك عرضه في السيرة الذاتية
  • طريقتك في الحديث عنه في المقابلة: «بنيت مشروعاً يستخدم Git Flow، مع CI على كل طلب سحب، وحماية فرع main، وإصدار معنون»
  • شكراً لكم — البرنامج ينتهي هنا، لكن المستودع يبقى لكم

الخطوة التالية بعد الورشة: طبّق نفس العملية على مشروعك الشخصي، وشارك الرابط معي للمراجعة.
