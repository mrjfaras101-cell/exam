جوهر هذه الورقةThe core of this worksheet

الهدف الحقيقي ليس «نسخ الملفات»، بل أن يفهم الطالب أن المستودع نسخة كاملة من التاريخ، وأن موقع الفريق يقرأ بياناته من ملفات JSON. من فهم هاتين النقطتين سيجد الورقة 03 (إضافة بطاقته) سهلة، ومن لم يفهمهما سيسأل عن كل خطوة.

The real goal is not copying files but understanding that a clone carries the whole history, and that the site renders from JSON data files. Students who grasp this will find Worksheet 03 straightforward.

الاستنساخ
Clone
◆ قبول★ 10 نقطة

معيار القبول:

$ git remote -v

أخطاء متوقعة وأسبابها التدريسية:

الخطأ الرسالة التي سيراها العلاج في التصحيح
نسخ المستودع (Download ZIP) بدل git clone فتظهر fatal: not a git repository لاحقاً −15 — إعادة إلزامية، لأن ZIP بلا تاريخ ولا .git
الاستنساخ داخل مستودع آخر مستودع متداخل (nested repo) وجّهه لإعادة الاستنساخ في projects/ نظيف
اختار مجلد C:\Windows أو سطح المكتب فوضى ملفات لا خصم، لكن وضّح قاعدة مجلد المشاريع
git remote -v فارغ نسخ ZIP نفس الحالة الأولى
مؤشر سريع في الجولةQuick tour check

اطلب من الطالب أن ينفّذ ls -a — من نجح في الاستنساخ سيرى مجلد .git. وجود .git هو الدليل القاطع أن المستودع صحيح وليس نسخة ZIP أو مجلد ملفات عادي.

2
بنية المشروع
Project structure
◆ فهم★ 20 نقطة

الإجابات النموذجية للجدول:

الملف دوره من يعدّله
index.html الهيكل الأساسي للصفحة: العنوان، شارة الفريق، حاويات البطاقات المدرّب/قائد الفريق أساساً، والطلاب لتحسينات
css/style.css كل التنسيقات والألوان وتخطيط البطاقات (يوجد قسم للطباعة) أصحاب مهام style
js/app.js يقرأ ملفات البيانات ويبني بطاقات HTML ويعرضها + البحث والتصفية أصحاب مهام الميزات
data/site-config.json إعدادات الموقع وجميع نصوصه العامة مشترك — نقاط تعارض متكررة
data/members/<username>.json بطاقتك: الاسم، الدور، الأمر المفضّل، الرسالة، الوسوم أنت فقط — لن تتعارض
data/members-index.json فهرس أسماء ملفات البطاقات (يقرأه الكود) مُولَّد آلياً — لا يُكتب يدوياً
tools/build-index.mjs يفحص مجلد البطاقات ويولّد الفهرس + النسخة المدمجة لا يُعدّل، يُنفّذ فقط
.gitignore قائمة ما لا يُتتبَّع (أسرار، ملفات نظام، مؤقتة) مشترك — نادر التعديل

معيار الدرجة: 2.5 نقطة لكل سطر صحيح (المجموع 20). الإجابة «ملف إعدادات» بلا تفصيل لا تكفي. الشرط المهم: أن يذكر أن الفهرس مُولَّد آلياً وأن ملف بطاقته خاص به.

أخطاء متوقعة: - خلط بين data/members-index.json وdata/members/ (يجب أن يفرّق بين الملف والمجلد). - كتابة أن 00-template.json و01-example-student.json ملفان «مهمان» — الأصح أنهما قالب ومثال يُنسخ منهما، وليسا بيانات فريق حقيقية.

3
تشغيل الموقع
Run the site
◆ قبول★ 15 نقطة

معيار القبول: دليل تشغيل حقيقي (صورة شاشة، أو مناقشة شفهية تحريرية أثناء الجولة، أو اسم ملف الصورة)، مع إجابة صحيحة على سؤال file:// مقابل http://.

الإجابات النموذجية: - عنوان الموقع: دليل فريق الصف (من data/site-config.json → siteTitle). - عدد البطاقات الافتراضي: 2 (01-example-student.json و99-you-instructor.json). - أي ملف جاء منه الاسم: data/site-config.json.

سؤال الفرق (المهم): عند الفتح المباشر file:// يمنع المتصفح fetch لملفات محلية لأسباب أمنية (سياسة المصدر الواحد CORS)، لذا يفشل تحميل JSON، ويعتمد المشروع على ملف مدمج مسبقاً data/members-bundle.js. الحل: تشغيل خادم محلي (python3 -m http.server أو Live Server) فيصبح العنوان http://localhost:8000 والقراءة مسموحة. وهذا هو نفس النمط الذي سيعمل به الموقع عند النشر على GitHub Pages.

توزيع درجات السؤال: 10 للمشاهدة العملية، 5 لصحة الإجابات الرقمية، 5 لتفسير فرق file:// وhttp://.

أخطاء متوقعة: نسيان Ctrl+Shift+R بعد التعديل فيرى نسخة قديمة؛ تشغيل الخادم من المجلد الأعلى فيظهر خطأ 404 على index.html.

4
مسار البيانات ودوال الكود
Data path and functions
◆ فهم★ 15 نقطة

الإجابات النموذجية:

الاسم في الكود وظيفته
DATA كائن ثوابت يجمع مسارات الملفات (config, index, membersDir, bundle)
fetchJSON() يحمّل ملفاً بصيغة JSON ويتحقق من نجاح الطلب (res.ok) وإلا يرمي خطأ
cardHTML() يبني قالب HTML لبطاقة عضو واحد (الاسم، الحرفان الأولان، الرابط، الدور، الأمر، الوسوم)
render() يعرض البطاقات المطابقة (بعد البحث والتصفية) داخل #membersGrid
window.MEMBERS_DATA نسخة مدمجة من البيانات تحمّلها الصفحة فقط عند تعذّر fetch (تشغيل file://)

تجربة إضافة اسم ملف غير موجود: تعمل الصفحة عادةً وتُظهر تنبيهاً في الطرفية فقط (تعذّر قراءة بطاقة / cannot read card …) لأن الكود يلتقط الخطأ داخل try/catch ويستمر في بقية البطاقات. الدرس: المرونة في التعامل مع البيانات الناقصة تجعل صفحة الفريق لا تنهار بسبب خطأ طالب واحد.

معيار الدرجة: 2 نقطة لكل دالة صحيحة (10) + 5 نقاط لنتيجة التجربة وتفسيرها. من كتب «تظهر رسالة خطأ حمراء ولا تظهر البطاقة الوحيدة» فقد فهم الفكرة جزئياً → 3 من 5.

5
قراءة تاريخ الفريق
Reading team history
◆ إتقان★ 25 نقطة

معيار القبول: 1. مخرجات git log --oneline -5 حقيقية من الجهاز (8 نقاط). 2. تحديد أكثر مساهم من git shortlog -sn (5 نقاط). 3. ذكر ملف عدّله زميلان — والجواب الصحيح في هذا المشروع هو data/members-index.json (وأيضاً data/members-bundle.js)، لأنهما يتغيّران مع كل بطاقة جديدة (7 نقاط). 4. جودة قراءة السجل: القدرة على شرح معنى عقدة الدمج (5 نقاط).

ملاحظة مهمة للمدرّب — حل مشكلة «الفرق الكاذب»: من ينفّذ git diff main..feature/x على فرع مدموج بالفعل سيرى حذفاً لا إضافة (لأن المقارنة تسير في الاتجاه المعاكس). الصحيح قبل الدمج:

$ git fetch origin
$ git log --oneline origin/main..feature/omar-qa-card     # الالتزامات الجديدة فقط
$ git diff --stat origin/main...feature/omar-qa-card      # ثلاثة نُقَط = مقارنة صحيحة

علّم الطالب الفرق بين النقطتين (..) والثلاث (...) — هذا يوفّر عليه لبساً في الورقة 04 و05 وسيظهر في التقييم.

سؤال ذكاء سريعA quick depth question

اسأل: «لماذا يظهر data/members-index.json في كل التزامات الفريق؟» الجواب المطلوب: لأنه يسجّل عدد البطاقات وقائمتها، فيتغيّر مع كل إضافة. تابع بالسؤال: «وهل هذا مشكلة؟» — الجواب: لا، لأن الحل أن يُعاد توليده لا أن يُحلّ يدوياً (وهو جوهر الورقة 05).

إجابات الأسئلةKnowledge-check answers
س1
clone مقابل pull
clone vs. pull
◆ فهم★ 5 نقطة

الإجابة النموذجية: git clone تُنشئ مستودعاً محلياً جديداً من الصفر مع كامل التاريخ وتربطه بـ origin — تُستخدم مرة واحدة لكل مشروع على كل جهاز. أما git pull فتحدّث مستودعاً موجوداً مسبقاً بجلب التحديثات الجديدة ودمجها — تُستخدم مراراً وعلى أساس يومي.

الدرجة: 3 نقاط للفرق «إنشاء أولي مقابل تحديث»، ونقطتان لذكر كامل التاريخ في clone.

س2
فشل الفتح المباشر
file:// failure
◆ تحليل★ 5 نقطة

الإجابة النموذجية: السبب سياسة أمان المتصفح التي تمنع fetch لملفات محلية عند العمل بنظام file://. الحل تشغيل خادم محلي (python3 -m http.server 8000 أو Live Server) ثم فتح http://localhost:8000، لأن الطلبات تصبح من مصدر http مسموح.

س3
لماذا لا تعارض في ملفات البطاقات
No conflict between cards
◆ تحليل★ 5 نقطة

الإجابة النموذجية: لأن كل طالب يضيف ملفاً جديداً بمسار مختلف (data/members/<username>.json)، وGit يتعامل مع إضافة ملفات مستقلة بدمج تلقائي بلا تعارض. التعارض يحدث فقط عند تعديل نفس السطور في نفس الملف — وهو ما سيحدث في data/members-index.json المشترك، ولذلك جعلناه مُولَّداً آلياً.

الدرجة: 3 نقاط لمبدأ «ملفات مختلفة = لا تعارض»، ونقطتان لاستنتاج أن المشكلة في الملف المشترك فقط.

ثلاث علامات خطر في هذه الورقةThree red flags
  1. نسخ ZIP بدل clone ← لن يستطيع الالتزام ولا الرفع، وسيعطّل الورقة 03.
  2. لا يستطيع تحديد ملف بطاقته ← سيعدّل ملف زميل ويصنع تعارضاً حقيقياً.
  3. يفتح data/members-index.json ليعدّله يدوياً ← سيصنع تعارضاً في كل مرة؛ أصلح هذا المفهوم الآن وليس في الورقة 05.
