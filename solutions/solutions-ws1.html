كيف تستخدم هذا النموذجHow to use this key

هذا الملف مرجعك أثناء التصحيح. لكل مهمة ستجد: معيار القبول الفعلي (ما الذي يجعل المهمة مكتملة)، والإجابة النموذجية، وأخطاء الطلاب المتوقعة وكيف تُحتسب درجاتها، وملاحظة تصحيح مختصرة. المبدأ الأساسي في التقييم: الدليل المُنتَج أهم من الإجابة الصحيحة — نحن ندرّب على مهارة عملية، لا على امتحان نظري.

This is your marking reference. For each task you get the acceptance criterion, the model answer, expected student mistakes and how they affect the mark, plus a short grading note. Guiding principle: produced evidence outweighs theoretical correctness.

قاعدة ذهبية في التصحيحGolden marking rule

لا تخصم على اختلاف المسارات أو أسماء الملفات أو أرقام الإصدارات، ولا على رسائل الخطأ في المرات الأولى. اخصم فقط على: دليل مفقود، أو فهم خاطئ يظهر في خطوة لاحقة، أو مخالفة قواعد الأمان (بيانات حساسة، --force على main).

إجابات المهام — المهام العمليةTask-by-task solutions
1
تثبيت Git والتحقق
Install and verify
◆ قبول★ 10 نقطة

معيار القبول: مخرجات حقيقية برقم إصدار (مثل git version 2.39.5) — لا مقتبسة من الورقة بلا تنفيذ. العلامة الخاصة بأنه نفّذ فعلاً: اختلاف رقم الإصدار عن رقم الورقة.

الإجابة النموذجية:

$ git --version
git version 2.43.0.windows.1

أخطاء متوقعة وطريقة احتسابها:

الخطأ الدلالة الخصم
كتب git –version بشرطة عربية/طويلة خطأ نسخ من مستند لا خصم — صحّح له فقط
لا يوجد أي دليل لم يُنفّذ −10
استخدم cmd بدل Git Bash مشكلة بيئة شائعة لا خصم، لكن أرشده الآن لتوفير وقته لاحقاً
command not found لم يُكمل التثبيت −4 مع إمهاله حتى نهاية الجلسة
ملاحظة تصحيحMarking note

تحقّق سريعاً أثناء الجولة على الطلاب: which git يجب أن يُخرج مساراً. هذا يمنع أكثر مشكلة تُعطّل الجلسة كلها (طالب يأخذ 20 دقيقة لأمر واحد).

2
ضبط الهوية
Configure identity
◆ قبول★ 10 نقطة

معيار القبول: البريد في git config --list مطابق لبريد حساب GitHub. هذا أهم بند في الورقة لأن خطأه يظهر متأخراً على شكل «التزامات باسم غريب» بلا صورة.

الإجابة النموذجية:

$ git config --list
user.name=سارة الحسن
user.email=sara@example.com
init.defaultbranch=main
pull.rebase=true
core.editor=code --wait

أخطاء متوقعة:

الحالة التشخيص العلاج/الخصم
إعداد البريد مختلف عن GitHub التزاماته ستظهر غير مرتبطة بحسابه −3 وأصلحها معه فوراً
إعداد محلي (--local) في مستودع فقط سيتكرر الخطأ في كل مستودع جديد −2
user.name أرقام أو لقب غريب يظهر في تاريخ المشروع −1 مع تنبيه على الأثر المهني
عمل git config --list من مجلد غير مستودع لا شيء — الأمر يعمل لا خصم
سؤال اطرحه على الطالبAsk the student

«لو أضفت التزاماً ببريد مختلف، كيف ستتحقّق من أن GitHub ربطه بحسابك؟» الجواب المتوقع: افتح صفحة الالتزامات أو git log --format="%an %ae" وقارن البريد والبريد المسجّل في إعدادات الحساب.

3
حساب GitHub مهني
Professional GitHub account
◆ قبول★ 15 نقطة

معيار القبول الثلاثي: (1) اسم مستخدم مهني، (2) بريد مؤكَّد، (3) 2FA مُفعَّل. النقطتان (2) و(3) تتحقّقان نظراً في الملف الشخصي — ولا تُقبل شهادة الطالب وحده.

معايير تقييم اسم المستخدم:

المستوى معيار مثال النقاط
ممتاز اسم + صفة مهنية sara-alhassan أو omar-qa 5
جيد اسم واضح بلا زخرفة sarahassan2026 3.5
مقبول مفهوم لكن غير مهني sara_student 2
ضعيف لا يعبّر xx_sara_xx أو asdfgh123 1

**قائمة تحقّق للمدرّب (استخدم صفحة الملف):

الفحص المكان في GitHub علامة ✔
البريد مؤكَّد Settings ← Emails
التحقق بخطوتين Settings ← Password and authentication
الصورة/الوصف الصفحة الرئيسية للملف الشخصي

أخطاء متوقعة: - طالب يرى 2FA «اختيارية» — وضّح أنها شرط تسليم لأن كل الطلاب ينشرون على مستودع مشترك. - طالب احتفظ برموز الاستعادة في متصفح الجهاز المشترك — نبّهه لحذفها فوراً (بند أمان). - طالب فقد الرمز وأصبح خارج حسابه — امنحه مهلة واحدة ولا تخصم، لكن سجّل الملاحظة.

حسّاسية أمنيةSecurity sensitivity

إذا رأيت رمز استعادة أو كلمة مرور مكتوبة على ورقة الطالب أو في ملف داخل المشروع: اخصم 5 نقاط وسجّل الحادث، وأبلغه أنه لا يجوز تخزين أسرار في مستودع — هذا درس الورقة 05 بخصوص الملفات المحذوفة من السجل.

4
تأمين الاتصال PAT أو SSH
PAT or SSH
◆ قبول★ 15 نقطة

معيار القبول: نجاح الاتصال فعلاً. للـ SSH: Hi <username>! You've successfully authenticated…. للـ PAT: نجاح git push أو git pull على مستودع خاص/عام بلا طلب كلمة مرور.

الإجابة النموذجية (SSH):

$ ssh-keygen -t ed25519 -C "sara@example.com"
$ cat ~/.ssh/id_ed25519.pub
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... sara@example.com

$ ssh -T git@github.com
Hi sara-alhassan! You've successfully authenticated, but GitHub does not provide shell access.

أخطاء متوقعة وخصوماتها:

الخطأ الدلالة الخصم
لا دليل تنفيذ، شرح فقط لم يُجرّب −15 (مع مهلة أثناء الجلسة)
نشر المفتاح الخاص (id_ed25519 بلا .pub) خطأ أمني خطير −5 + إبلاغ فوري وحذف المفتاح
PAT بصلاحيات كاملة (repo + admin:org + delete_repo) تجاوز مبدأ أقل صلاحية −3
PAT بلا تاريخ انتهاء مخاطرة دائمة −1
حفظ PAT في ~/.git-credentials على جهاز مشترك خطر أمني −4
ملاحظة تصحيح عمليةPractical marking note

أسرع اختبار: اطلب من الطالب تنفيذ git ls-remote <رابط المستودع> — إن ظهرت قائمة المراجع (refs) بلا طلب كلمة مرور فالاتصال سليم.

5
بيئة العمل: VS Code والطرفية
Workspace setup
◆ قبول★ 10 نقطة

معيار القبول: pwd وls من مجلد المشاريع، و VS Code يعمل، وإضافة واحدة على الأقل (GitLens هي الأهم للأهداف التدريبية).

أخطاء متوقعة: نُفّذ الأمر من C:\Windows\System32 (مجلد افتراضي على Windows) → وجّهه إلى مجلد المشاريع. الطالب لم يفتح الطرفية المدمجة بل استخدم نافذة منفصلة → لا خصم، لكن ذكّره بأن الطرفية المدمجة تفتح على مسار المشروع تلقائياً وتوفّر عليه cd.

6
المستودع الأول: clone → commit → push
First repo cycle
◆ إتقان★ 25 نقطة

معيار القبول (خمسة عناصر):

العنصر ما أبحث عنه النقاط
المستودع أُنشئ وصار عاماً رابط صالح يفتح للزائر 5
الاستنساخ نجح مجلد محلي + git remote -v يُظهر origin 5
التعديل موجود على GitHub فتح الرابط ورؤية السطرين المضافين 5
رسالة التزام صحيحة صيغة type(scope): وصف ولو مبدئية 6
git log --oneline في الدليل سطران: Initial commit + التزامه 4

الإجابة النموذجية:

$ git log --oneline
3f1a9c2 (HEAD -> main, origin/main) docs(readme): add a short personal introduction
9d4b1a7 Initial commit

$ git status
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean

أخطاء متوقعة وخصوماتها:

الخطأ الدلالة الخصم
التعديل موجود محلياً فقط (بلا push) خلط بين commit و push −8 (وهو هدف التعلم الأساسي)
رسالة الالتزام update أو first commit فقط لا معنى للمراجع −2
git status غير نظيفة عمل غير مكتمل −2
استخدم واجهة GitHub للتحرير لا الطرفية تجاوز التمرين −6 (أعد تكليفه بالطرفية)
أنشأ ملفات مشروع كاملة بدل تعديل README تفوق لا خطأ لا خصم، أشر إلى تميّزه
اختبار الحقيقة الواحدThe one truth test

افتح رابط المستودع في متصفحك: هل ترى السطر الذي أضافه الطالب في README.md وهل الرسالة تظهر باسمه وصورته؟ إن كانت الصورة الافتراضية (identicon رمادي)، فبريده مختلف عن بريد حساب GitHub — راجع المهمة 2 واطلب التصحيح.

إجابات أسئلة التحقّقKnowledge-check answers
س1
الفرق بين add و commit
add vs. commit
◆ فهم★ 3 نقطة

الإجابة النموذجية: git add ينقل التعديل من مجلد العمل إلى منطقة الانتظار (لا يحفظ شيئاً في التاريخ)، وgit commit يحوّل ما في منطقة الانتظار إلى التزام محفوظ في المستودع المحلي برسالة تعريفية. نحتاجهما معاً لأن منطقة الانتظار تسمح باختيار ما يدخل الالتزام بدقة (مثلاً: بطاقتي + الفهرس، دون ملفات تجريبية).

معيار منح الدرجة: 2 نقطة للفصل الصحيح بين المنطقتين + 1 نقطة لذكر فائدة الاختيار الانتقائي. الإجابة «add يحفظ و commit يرفع» خاطئة (الخطأ يخلط مع push) → 0.

س2
لماذا لا يرى الزميل التعديل
Why the teammate sees nothing
◆ تحليل★ 3 نقطة

الإجابة النموذجية (احتمالان): 1. لم يُرفع العمل: التعديل التُزم محلياً لكن git push لم يُنفّذ، فهو على جهاز الطالب فقط. 2. رفع على فرع غير main: الالتزام موجود على فرع feature/... ولم يُدمج بعد، والصفحة تقرأ من main.

إجابات مقبولة إضافية: كان الزميل يقرأ نسخة مخزّنة في المتصفح (نادر)، أو الطالب رفع إلى مستودع مختلف (fork) بلا طلب سحب.

معيار الدرجة: 1.5 نقطة لكل احتمال صحيح، بحد أقصى 3. الإجابة «لم يحدّث المتصفح» → نقطة واحدة فقط مع تنبيه.

س3
أوامر الحالة والسجل
State and log commands
◆ حفظ تطبيقي★ 3 نقطة

الإجابة النموذجية: (أ) git status (أو git status -sb للصيغة المختصرة). (ب) git log --oneline (والمقبول أيضاً git log --oneline --graph).

خصم شائع: كتابة git status لطلب «آخر الالتزامات» → 1.5 من 3. كتابة git log وحدها بلا --oneline → 2.5 (تفي بالغرض لكنها ليست كما طُلب).

س4
أهمية الهوية المهنية
Why professional identity matters
◆ تحليل★ 3 نقطة

الإجابة النموذجية (سببان): (1) المراجع في طلب السحب يعرف من صاحب التعديل ويثق به أسرع؛ (2) التاريخ (log/blame) يبقى مفهوماً، فيعرف الفريق من يسأل عند خطأ في ملف معيّن؛ (3) الانطباع الأول عند المشاركة في مشروع مفتوح المصدر أو التقدّم لفرصة تدريب.

معيار الدرجة: نقطتان لأي سببين صحيحين مرتبطين بالعمل الجماعي، ونقطة إضافية لذكر التاريخ/التتبّع تحديداً. إجابات عامة («حتى تبدو محترماً») → نقطة واحدة.

س5
اختلاف البريد
Mismatched email
◆ تحليل★ 3 نقطة

الإجابة النموذجية: لن يُربط الالتزام بحساب GitHub؛ سيظهر باسم المستخدم المُعدّ محلياً بصورة افتراضية، ولن يُحتسب في إحصاءات المساهمات (Contribution graph)، وقد يظهر التزام غير موثّق (Unverified). الحل: إعادة الإعداد بالبريد الصحيح ثم git commit --amend --reset-author للالتزامات غير المرفوعة.

معيار الدرجة: نقطتان لذكر «عدم ربط/إحصاءات» + نقطة لذكر حل التصحيح. الإجابة التي تقول «لن يُحفظ الالتزام» → 0 لأنها فهم خاطئ.

علامات الخطر المبكرةEarly warning signs

هذه الأنماط تُنبئ بمشكلات في الأوراق التالية — تدخّل فيها الآن لا لاحقاً: 1. لا يوجد أي دليل مخرجات في الورقة كلها ← الطالب لم ينفّذ، سيتراكم عليه العمل. 2. git مثبّت لكن الهوية خاطئة ← ستظهر التزاماته مجهولة على GitHub في الورقة 03. 3. لا 2FA ولا PAT/SSH ← سيتوقف في أول git push ويتعطّل بقية الجلسة. 4. يعمل على جهاز مشترك دون فهم مسار المشروع ← خطر عمل في مجلد النظام. 5. يقول «فعلت» بلا دليل ← نبّهه أن الورقة تُقيّم بالأدلة، وأعد التمرين عليه.
