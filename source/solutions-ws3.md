:::bi
هنا ينتقل الطالب من «التعلّم عن Git» إلى **العمل بمنهج فريق حقيقي**. فتّش في تصحيحك عن
ثلاثة أشياء بالترتيب: **(1)** هل التزم بالفرع وطلبه؟ **(2)** هل الالتزامات واضحة ومفيدة؟
**(3)** هل شارك في المراجعة بجدية (مكتوبة ومحدّدة) أم كتب «موافق»؟ التقييم يجب أن يرفع
وزن المراجعة، لأنها المهارة التي تحوّل الطالب إلى عضو فريق لا مجرد كاتب كود.
---EN---
This is where students become team members. Prioritise three things: did they follow the
branch + PR workflow, are their commits meaningful, and did they review a teammate's work
substantively — not a bare “LGTM”.
:::

:::band{type="alt" ar="جدول التقييم المُجمَّع" en="Marking rubric"}
:::

| # | المهمة | النقاط | معيار القبول الأساسي | ملاحظة تصحيح |
|---|---|---|---|---|
| 1 | مزامنة + Issue | 10 | رقم Issue حقيقي في مستودع الفريق | Issue مفتوح بوصف واضح |
| 2 | إنشاء الفرع | 10 | الاسم مطابق للاتفاقية `feature/<user>-card` | خصم على أسماء غامضة |
| 3 | ملف البطاقة + الفحص | 20 | `validate-members.mjs` = 0 خطأ | الفحص هو الحكم لا الشكل |
| 4 | الالتزام والرفع | 20 | التزام برسالة صحيحة + `push -u` ناجح | يقيس جودة الرسالة فعلياً |
| 5 | طلب السحب + المراجعة | 20 | PR مكتمل + مراجعة زميل مكتوبة | نصف الدرجة للمراجعة |
| 6 | الاستجابة للملاحظات | 10 | التزام إضافي على نفس الفرع بعد ملاحظة | يقيس مهارة العمل الجماعي |
| — | الأسئلة (س1–س4) | 10 | — | إجابة عملية لا نظرية |

:::box{type="rule" ar="معيار «المساهمة الكاملة»" en="Full-contribution standard"}
لا تُمنح درجة كاملة لمن لم يُدمج أو لم يُراجع. الحد الأدنى للتسليم المقبول: بطاقة صحيحة
مدموجة/تحت المراجعة، **+** مراجعة مكتوبة واحدة على عمل زميل. المراجعة ليست إضافية —
هي نصف قيمة هذه الورقة.
:::

:::task{num="1" ar="المزامنة والمهمة (Issue)" en="Sync and issue" pts="10" level="قبول"}

**معيار القبول:** مخرجات `git pull --ff-only` (يُقبل `Already up to date`) + رقم Issue
حقيقي يمكن فتحه.

**الإجابة النموذجية:**
```text
$ git switch main
$ git pull --ff-only
remote: Enumerating objects: 12, done.
Updating 8de1e7a..a1b2c3d
Fast-forward
 data/members/ali-h.json | 9 +++++++++
 1 file changed, 9 insertions(+)
```

**أخطاء متوقعة:** بدأ العمل مباشرة دون سحب → **−4** (وسيظهر أثره كتعارض في الورقة 05).
عنوان Issue عام («مهمة») → −2. لم يفتح Issue إطلاقاً → −6 مع السماح بفتحه أثناء الجلسة.

:::box{type="tip" ar="طريقة تحقّق سريعة" en="Fast verification"}
افتح تبويب `Issues` في مستودع الفريق: يجب أن ترى عدداً من المهام يقارب عدد الطلاب، وعنوان
كل مهمة يذكر اسم المستخدم. هذا يثبت أن الجميع بدأ من نقطة صحيحة — وتكلفته 30 ثانية.
:::
:::

:::task{num="2" ar="إنشاء الفرع" en="Create the branch" pts="10" level="قبول"}

**معيار القبول:** اسم فرع بصيغة `type/username-topic` وحروف إنجليزية صغيرة وشرطات فقط،
مع نجمة `*` على الفرع الصحيح في `git branch`.

**أمثلة مقبولة:** `feature/omar-qa-card` · `feat/omar-qa-card` · `add/omar-qa-card`
**أمثلة مرفوضة وخصوماتها:**

| الاسم | المشكلة | الخصم |
|---|---|---|
| `my-branch` | لا يدل على صاحبه ولا موضوعه | −3 |
| `omar_card` | شرطة سفلية (المعيار = شرطات) | −1 |
| `فرع-عمر` | حروف عربية ومسافات تسبب مشاكل في الأدوات | −2 |
| `omar/final/final2` | مسارات متعددة وتسمية فوضوية | −2 |
| `main` (عمل على الفرع الرئيسي) | **مخالفة جسيمة** | −10 وإعادة فورية |

**مهارة يجب التحقق منها:** أن يعرف الطالب الإجابة على «على أي فرع أنا الآن؟» —
إما `git branch` أو `git branch --show-current` أو `git status -sb`.
:::

:::task{num="3" ar="ملف البطاقة والفحص" en="Card file and validation" pts="20" level="إتقان"}

**معيار القبول القاطع:** مخرجات
`--- النتيجة / Result: 6 بطاقة، 0 خطأ، 0 تحذير ---`.
التحذيرات لا تمنع القبول لكنها تستحق ملاحظة تصحيح.

**مثال بطاقة صحيحة:**
```json
{
  "fullName": "عمر القاسم",
  "github": "omar-qa",
  "role": "مختبر QA",
  "favoriteCommand": "git log --oneline --graph --all",
  "message": "أبحث عن الأخطاء قبل أن يجدها المستخدم، وأثبت كل إصلاح بمخرجات واضحة.",
  "tags": ["Testing", "JavaScript"],
  "joinedAt": "2026-10-06"
}
```

**خريطة الأخطاء التي يكتشفها الفحص ورموزها:**

| رسالة الفحص | السبب | الدرجة |
|---|---|---|
| `حقل مفقود: "message"` | الحقل غير موجود أو فارغ | −4 |
| `اسم مستخدم غير صالح` | حرف كبير أو `_` أو رموز | −3 |
| `الامر المفضل يجب ان يبدا بـ "git "` | كتب `ls` أو `npm start` | −3 |
| `طول الرسالة 8 — يجب أن يكون بين 10 و140` | رسالة قصيرة جداً | −2 |
| `دور غير معتاد` | دور خارج القائمة المعتمدة | −2 (تحذير فقط) |
| `بيانات حساسة أو ممنوعة` | بريد/هاتف/كلمة مرور | **−8 + تحقيق** |
| `البطاقة غير مُفهرسة` | لم يُنفّذ `build-index.mjs` | −4 |
| `اسم مستخدم مكرر مع` | انتحل اسم زميل | **−10 + إعادة** |
| `اسم الملف لا يطابق اسم المستخدم` | `my-card.json` بدل `omar-qa.json` | تحذير −1 |

:::box{type="err" ar="تنبيه إلزامي على بيانات شخصية" en="Mandatory personal-data check"}
افحص كل بطاقة بعينك بحثاً عن: بريد شخصي، رقم هاتف، عنوان سكن، اسم مدرسة/جامعة مع تفاصيل
تعريفية، اسم أحد الوالدين. أي واحدة منها تُحذف من ملف موجود في مستودع عام — وهذا جزء من
تدريبهم على الخصوصية الرقمية. إن تجاوزت الفحوص ولم تكتشفها، فالمسؤولية على المشروع.
:::
:::

:::task{num="4" ar="الالتزام والرفع" en="Commit and push" pts="20" level="إتقان"}

**معيار القبول:** التزام برسالة بصيغة `Conventional Commits` + نجاح `git push -u` +
`git branch -vv` يُظهر الربط `[origin/feature/...]`.

**الإجابة النموذجية:**
```text
$ git add data/members/omar-qa.json data/members-index.json data/members-bundle.js
$ git commit -m "feat(members): add card for omar-qa"
[feature/omar-qa-card 89f5cff] feat(members): add card for omar-qa
 3 files changed, 25 insertions(+), 2 deletions(-)
 create mode 100644 data/members/omar-qa.json

$ git push -u origin feature/omar-qa-card
 * [new branch]      feature/omar-qa-card -> feature/omar-qa-card
branch 'feature/omar-qa-card' set up to track 'origin/feature/omar-qa-card'.
```

**سلّم تقييم رسالة الالتزام (أهم 6 نقاط في المهمة):**

| المستوى | مثال | النقاط |
|---|---|---|
| ممتاز | `feat(members): add card for omar-qa` | 6 |
| جيد | `feat: add omar card` | 4.5 |
| مقبول | `add my card file` | 3 |
| ضعيف | `update` / `changes` / `add` | 1 |
| مرفوض | `final` / `asdf` / `.` / `.` / رسالة فارغة | 0 |

**أخطاء متوقعة:**

| الخطأ | العلاج | الخصم |
|---|---|---|
| التزم لكن لم يرفع | أهم خطأ — اسأله: «أين عملك الآن؟» | −6 |
| رفع على `main` | تحقّق أنه يحترم حماية الفرع | −10 |
| التزامان برسالتين فوضويّتين لنفس الملف | يقبل 3 نقاط من 6 للرسائل | −3 |
| `git add .` وحده | أضاف ملفات غير مقصودة | −2 مع مناقشة الدرس |
| نسخ مخرجات الورقة بدل مخرجات جهازه | **صفر** في المهمة + تحقيق شفافية | −20 |
| استخدم `--force` بلا سبب | ذكر توجيه الورقة 05 | −3 |

:::box{type="warn" ar="كيف تكتشف أدلة منسوخة من الورقة؟" en="Spotting copy-paste evidence"}
علامات واضحة: مخرجات المهمة الرقم 4 يظهر فيها بريد `nour@example.com` أو hash مطابق
تماماً لحروف الورقة (`89f5cff`)، أو اسم بطاقة لعضو آخر، أو رسالة `feat(members): add card
for omar-qa` بينما الطالب اسمه سارة. اطلب منه تنفيذ الأمر أمامك في جولة سريعة، وسجّل
ملاحظة «دليل غير شخصي» تخصم فيه من بند الأدلة (لا من فهمه التقني).
:::
:::

:::task{num="5" ar="طلب السحب والمراجعة" en="Pull request and review" pts="20" level="إتقان"}

**معيار القبول — خمسة عناصر، كل عنصر 4 نقاط:**

| # | العنصر | ما أراقبه |
|---|---|---|
| 1 | PR مفتوح للفرع الصحيح | `base: main` ← `compare: feature/<username>-card` |
| 2 | عنوان مطابق للاتفاقية | نفس صيغة رسالة الالتزام |
| 3 | القالب مملوء | ماذا تغيّر + الأدلة + طريقة الاختبار |
| 4 | `Closes #<issue>` مذكور | يربط المهمة بالطلب |
| 5 | مراجعة زميل **مكتوبة ومحدّدة** | تعليق على ملف أو سطر، لا «موافق» |

**سلّم تقييم جودة المراجعة (بند حرج — 6 نقاط):**

| المستوى | مثال تعليق | النقاط |
|---|---|---|
| ممتاز | «سطر 6: الأمر `npm start` لا يبدأ بـ `git`، هل تقصد `git status`؟ اقترح تعديلاً.» | 6 |
| جيد | «الحقل `message` أقل من 10 أحرف، يُفضّل توضيح أدوارك.» | 4.5 |
| مقبول | «البطاقة صحيحة، لكن الوسوم فارغة — ممكن تضيف JavaScript؟» | 3 |
| ضعيف | «ممتاز ✔» | 1.5 |
| مرفوض | لا تعليق / «موافق» / نقد شخصي | 0 |

**أخطاء متوقعة:**
- دمج الطالب فرعه بنفسه (`Merge pull request`) → **−15** (بند صريح في الورقة).
- كتابة التعليق بلغة غير مهنية أو سخرية → **−6 + جلسة إرشاد**.
- مراجعة PR لنفسه (لا فائدة) → 0 في هذا البند.
- لم يطلب Reviewer محدداً → −2.

:::box{type="tip" ar="سكربت الجولة السريعة على GitHub (3 دقائق لكل فريق)" en="Fast GitHub tour"}
لكل طالب: افتح صفحته `github.com/<username>` → تبويب `Activity` أو سجّل الدخول إلى
المستودع ← `Pull requests` ← صفِّ بـ `author:<username>`. تحقّق من: العدد، العنوان،
المراجعات، ومن فتح PR ولم يُدمج. هذا يعطيك لوحة تقييم حقيقية بلا أوراق.
:::
:::

:::task{num="6" ar="الاستجابة للملاحظات" en="Responding to feedback" pts="10" level="سلوك مهني"}

**معيار القبول:** التزام إضافي على **نفس الفرع** بعد ملاحظة المراجع + طلب السحب تحدّث
تلقائياً (لا يُنشأ PR جديد).

```text
$ git add data/members/omar-qa.json
$ git commit -m "fix(members): add JavaScript tag per review feedback"
[feature/omar-qa-card 3c7d9e1] fix(members): add JavaScript tag per review feedback

$ git push
   89f5cff..3c7d9e1  feature/omar-qa-card -> feature/omar-qa-card
```

**أخطاء متوقعة:** فتح PR جديد للتعديل الصغير (0) — علّمه أن PR الجديد يفقد سياق المراجعة.
الاعتراض على الملاحظة بلا تنفيذ ولا شرح مقنع (3 من 10). الالتزام برسالة `fix` واضحة
وبدون تفصيل كافٍ (6 من 10).

:::box{type="info" ar="مؤشر نضج مهني — راقبه" en="Professional maturity signal"}
الطالب الذي يرد على الملاحظة بـ «رأيك صحيح، عدّلتُ الملف والتزمت، وما زلت أعتقد أن الوسم
إضافي لكن لا مشكلة» — هذا **أعلى مستوى** في الورقة الثالثة: يتقبّل النقد، ينفّذ، ويحافظ
على رأيه باحترام. اذكر هؤلاء في تقرير الفريق.
:::

:::task{num="س1" ar="-c في switch" en="switch -c" pts="2.5" level="فهم"}
`git switch -c feature/x` تُنشئ فرعاً جديداً وتنتقل إليه في خطوة واحدة. أما
`git switch feature/x` فتنتقل إلى فرع **موجود مسبقاً** فقط، وستفشل إن لم يكن موجوداً
(`fatal: invalid reference`).
:::

:::task{num="س2" ar="لماذا المزامنة قبل الفرع" en="Why sync first" pts="2.5" level="تحليل"}
لأن الفرع الجديد يتفرّع من **النقطة الحالية** لـ `main`. فلو كان `main` قديماً، فستبني
عملك على أساس ناقص، وسيظهر لاحقاً كتعارض أو كعدد هائل من «الالتزامات الغريبة» في طلب
سحبك، وسيضطر المراجع للمقارنة مع نسخة قديمة.
:::

:::task{num="س3" ar="معنى Closes #12" en="Closes #12" pts="2.5" level="استخدام"}
تعني «هذا الطلب يُنهي المهمة رقم 12» — فيربط GitHub الطلب بالمهمة، وينشئ مرجعاً تلقائياً
في الطرفين، **ويُغلق المهمة تلقائياً** عند دمج طلب السحب. فائدتها: تنظيم، وإثبات أن العمل
استهدف مهمة معروفة، ومنع العمل المهدور على مهام منتهية.
:::

:::task{num="س4" ar="رسالة التزام صحيحة" en="Write a valid commit" pts="2.5" level="تطبيق"}
**الإجابة النموذجية:** `fix(ui): correct card alignment on mobile`
(مقبول أيضاً: `fix(css): fix card alignment on mobile screens`).

**معيار الدرجة:** 1 نقطة للنوع `fix`، نقطة للنطاق `(ui)` أو `(css)`، ونصف لوصف واضح
بصيغة الأمر وبالإنجليزية. رسالة عربية بلا نوع → نصف الدرجة فقط.
:::

:::box{type="ok" ar="قائمة تحقّق المدرّب على المستودع (قبل إغلاق الجلسة)" en="Instructor repo checklist"}
```text
1) Pull requests: عددها = عدد الطلاب (٧ أو ١٠)، وأي طالب بلا PR؟
2) Issues: كل مهمة مرتبطة بـ Closes #n في وصف PR؟
3) Files changed: هل ظهر ملف غريب (مثل .env أو صورة شخصية أو مفتاح)؟
4) هل عدّل أحدهم ملف زميل؟ (git log --data/members/<other>.json)
5) node tests/validate-members.mjs  ←  0 خطأ على main بعد الدمج
6) حماية فرع main مُفعَّلة: Settings ← Branches ← Require pull request before merging  ✓
```

:::box{type="warn" ar="استعداد للورقة 04" en="Preparing for Worksheet 04"}
من أنهى هذه الورقة تماماً: بطاقة **مدموجة** على `main`. من تأخر: بطاقة على فرع مرفوع
ومفتوح بطلب سحب. المجموعة الثانية ستواجه الورقة 04 بظروف مختلفة (ديون دمج) — وهذه ليست
مشكلة بل فرصة تدريبية، لكن رتّب المجموعتين في زوجين متكاملين حتى لا يبقى أحد بلا مهام.
:::
