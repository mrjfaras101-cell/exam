# مُصحِّح — تصحيح أوراق الاختبارات بالكاميرا

تطبيق يمنح المعلم **ورقة إجابة واحدة** يطبعها، ويقرأها لاحقًا بكاميرا الجوال فيُخرج درجة كل طالب
فورًا — بدون إنترنت، وبدون رفع أي صورة إلى أي خادم.

**الوعد:** 30 ورقة تُصحَّح في أقل من 3 دقائق، وتقرير يُظهر الأسئلة المعيبة (صعبة/سهلة/لا تميّز/مفتاح مشكوك فيه).

---

## 1. نطاق المشروع (المثبَّت)

| البند | القرار |
|---|---|
| المنصة | Flutter — أندرويد + آيفون |
| حجم الورقة | A4 واحدة، وجه واحد |
| عدد الأسئلة | حتى 20 سؤالًا |
| حجم الصف | حتى 30 طالبًا |
| أنواع الأسئلة | **فقط**: «ضع دائرة حول رمز الإجابة الصحيحة» و«أجب بنعم أو لا» |
| تعريف الطالب | شبكة رقم الجلوس تُظلَّل وتُقرأ آليًا |
| مفتاح الإجابة | يلمسه المعلم، أو يمسح «ورقة مفتاح» مطبوعة — ويُخزَّن مرتبطًا برقم الاختبار |
| الخصوصية | كل المعالجة على الجهاز، لا رفع، لا إعلانات، لا تحليلات |

**المبدأ الحاكم:** لا يوجد تخمين صامت. أي شكّ في قراءة فقاعة → وسم «يحتاج مراجعة» + تعديل يدوي بلمسة.

## 2. ماذا يوجد في هذا المستودع

```
exam/
├── docs/01-design-ar.md    وثيقة التصميم الكاملة (التفكير العميق بالتفاصيل + الحالات الحدّية + العتبات)
├── demo/                   نسخة ويب تجريبية كاملة تعمل بلا بناء — للتجربة الفورية على المتصفح
├── app/                    تطبيق Flutter (المنتج النهائي)
├── assets/fonts/           خط Cairo (رخصة OFL) — مطلوب للعرض العربي على canvas وفي PDF
└── demo/test/              اختبارات المحرّك + مولّد أوراق اصطناعية واقعية (Python/Pillow)
```

### أ) تجربة الويب (أسرع طريقة لرؤية كل شيء الآن)

```bash
cd demo
python3 -m http.server 8000
# ثم افتح: http://localhost:8000
```

- زر **«تجريبي»** يقرأ 6 أوراق اصطناعية جاهزة (من `demo/assets/samples/`) ويصحّحها ويعرض النتائج والتحليل — دون كاميرا.
- «مسح ورقة المفتاح» يقرأ `keysheet.jpg` ويستخرج المفتاح.
- زر الطباعة يعرض الورقة بمقاس A4 حقيقي (تحذير «مقياس 100%»).

### ب) تطبيق Flutter (المنتج)

```bash
cd app
flutter pub get          # يتطلب Flutter 3.27+ (Dart 3.6+)
flutter analyze
flutter test             # اختبارات المحرّك والتصحيح (بلا جهاز)
flutter run
```

إذا كانت مجلدات المنصات غير موجودة بعد (أول مرة):

```bash
cd app
flutter create .                       # يولّد android/ وios/ ... مع الحفاظ على lib/
python3 tool/apply_platform_config.py  # يضيف صلاحية الكاميرا (أندرويد) ووصف الاستخدام (iOS)
```

التفاصيل الكاملة (الصلاحيات، البنية، المعايرة، حدود النسخة الحالية) في **[`app/README.md`](app/README.md)**.

## 3. كيف يعمل المحرّك (باختصار)

الورقة هي «عقد» بين الطباعة والقراءة: كل فقاعة لها إحداثيات معلومة بالمليمتر، والقراءة **قياس** لا تخمين.

1. **4 علامات تسجيل** في الأركان (والمربع الرابع حلقيّ) → إيجاد الأركان + فرض الاتجاه حتى لو قُلبت الورقة 180°.
2. **تصحيح إضاءة نسبي** (قسمة على الخلفية المموّهة) + **Otsu** للعثور على العلامات.
3. **تجانس Homography** يحوّل إحداثيات المليمتر إلى البكسل → نعرف مكان كل فقاعة بدقة.
4. **قياس الحبر لكل فقاعة**: قرص العيّنة بين 0.42 و0.70 من نصف القطر (يتجنّب خط الدائرة المطبوع)،
   والبياض المحلي من حلقة خارج الدائرة (1.2–1.5 r) كي لا يتلوّث الحبر بالخط المطبوع.
5. **قرار متعدّد العتبات**: ≥0.45 مظلَّلة، 0.18–0.45 خفيفة (تُقبل + وسم)، أقل من ذلك فارغ،
   مع فرع تسامح للتظليل الباهت جدًا (قلم رصاص) — وكل حالة شكّ تصبح «مراجعة».
6. **قراءة رقم الجلوس** من شبكة الأرقام المظلَّلة، و**رمز الورقة** (6 بتّات) يميّز رقم الاختبار وورقة المفتاح.
7. **التقاط تلقائي متتابع**: لا يضغط المعلم زرًا؛ يُلتقط الورق عند اتفاق قراءتين متتاليتين وثبات الأركان.

القيم الافتراضية للعتبات (وهي قابلة للمعايرة من شاشة الإعدادات):

| المعامل | القيمة | المعامل | القيمة |
|---|---|---|---|
| عتبة «مظلّلة» | 0.45 | الحد الأدنى للدقة | 3.5 بكسل/مم |
| عتبة «خفيف» | 0.18 | وسم دقة منخفضة | < 5.2 بكسل/مم |
| نسبة الحبر/البياض | 0.74 | رفض الاهتزاز/البعد | عرض حرف > 2.4 مم |
| عتبة رمز الورقة | 0.42 | وسم اللمعان | > 30% من الورقة |

## 4. الاختبارات

```bash
# اختبارات النسخة الويب (Node.js — بلا تبعيات)
node demo/test/dump_template.mjs                 # تصدير القالب والمفتاح والطلاب
python3 -m venv /home/user/.venv && /home/user/.venv/bin/pip install pillow numpy   # مرة واحدة
/home/user/.venv/bin/python demo/test/gen_scans.py --count 6        # أوراق اصطناعية واقعية
node demo/test/run_tests.mjs                    # الاختبار التكاملي: قراءة كاملة للأوراق
node demo/test/grading_test.mjs                 # اختبار قواعد التصحيح والتحليلات

# اختبارات تطبيق Flutter (تحتاج SDK)
cd app && flutter test
```

نتيجة الاختبار التكاملي الحالية: **6/6** أوراق مقروءة (رمز الورقة، رقم الجلوس، كل الإجابات)،
ودقة الأركان ≤ 0.5 بكسل، وزمن ~150 مللي ثانية للورقة، مع حالات مُغطّاة: تظليل خفيف/باهت/مزدوج/فارغ،
ورقة مقلوبة، دقة منخفضة، ورق فوتوكوبي.

## 5. حالة المشروع (بصراحة)

| المكوّن | الحالة |
|---|---|
| التصميم الكامل + العتبات + الحالات الحدّية | ✅ `docs/01-design-ar.md` |
| محرّك القراءة (JS + Dart) | ✅ مُعاير ومُختبَر على أوراق اصطناعية |
| نسخة الويب التجريبية | ✅ تعمل — جُرِّبت آليًا (كل المسارات 200) |
| قواعد التصحيح والتحليلات | ✅ مُختبَرة (19 تأكيدًا في JS + نسخة Dart) |
| تطبيق Flutter الكامل (7 شاشات + تخزين + PDF + كاميرا) | ⚠️ **الكود مكتوب كاملًا لكنه لم يُصرَّف بعد** — بيئة كتابته كانت بلا Flutter SDK. شغّل `flutter analyze` أولًا |

**أول ما يجب فعله بعد فتح المشروع على جهاز فيه Flutter:** `flutter analyze` ثم `flutter test`،
ثم طباعة ورقة واحدة ومسحها لضبط العتبات على طابعة المدرسة ونوع القلم المستخدم.
