1 · فلسفة البرنامج ونتائجه1 · Programme philosophy & outcomes

البرنامج مبني على مبدأ واحد: يُتعلّم Git بالعمل الجماعي فقط. لذلك يبدأ كل طالب بعمل خاص به (بطاقته)، ثم يرى عمل زملائه، ثم يواجه تعارضاً حقيقياً ويحلّه، ثم يُنشَر النتيجة للعالم. في نهاية البرنامج يكون المتدرب قادراً على العمل كعضو فريق في مستودع حقيقي — لا أن يحفظ أوامر فقط.

The programme rests on one principle: Git is learned through real collaboration. Each trainee owns a personal artefact (their card), sees teammates' work, resolves a genuine conflict, and ships the result publicly.

النتائج التدريبية المتوقعة (Measurable outcomes):

# النتيجة كيف تُقاس
1 إنشاء حساب ومستودع وإعداد بيئة عمل مؤمَّنة ورقة 01 — الأدلة السبعة
2 استنساخ مشروع حقيقي وفهم بنيته وتشغيله محلياً ورقة 02 — دليل التشغيل + جدول البنية
3 مساهمة كاملة: فرع → التزام → رفع → طلب سحب → مراجعة ورقة 03 — رقم PR + مراجعة مكتوبة
4 مزامنة عمل الفريق وفهم استراتيجيات الدمج ورقة 04 — مخرجات الدمج + تقرير الفريق
5 حل التعارضات بأمان والنشر على الإنترنت ورقة 05 — دليل تعارضين + رابط منشور
مبدأ التصميم التربويInstructional design principle

كل ورقة = دورة تعلّم كاملة: مفهوم قصير → تنفيذ على الجهاز → دليل مخرجات → تحقّق ذاتي → تسليم. لا يوجد بند نظري بلا تنفيذ مقابله، ولا تنفيذ بلا دليل يثبته. هذا يقلّل «الحفظ الأعمى» ويمنحك أنت أدلة قابلة للمطابقة.

إدارة الوقت — أشد مشكلة في هذه الورشةTime management

90% من التأخير سببه طالب واحد عالق في تثبيت أو أمر خاطئ. الحلول المجرَّبة: 1. زميل مساعد: عيّن الطالب الأسرع «مساعد الجلسة» يتحرك بين الصفوف (وليست مهمة إدارية بل تدريبية). 2. مهل زمنية مرئية: اكتب على السبورة وقت نهاية كل مهمة، ونادِ عند الانتقال. 3. لا تحلّ جهاز طالب بيدك: اسأل «ماذا تقرأ في هذه الرسالة؟» واتركه ينفّذ. 4. شريحة زمن احتياطية: اترك آخر 10 دقائق بلا محتوى جديد دائماً.

محاكاة بدون إنترنت (سكربت الإنقاذ)Offline contingency plan

إذا سقط الإنترنت (شائع في القاعات)، لا تُلغِ الجلسة. استخدم مستودعاً محلياً وهمياً:

# على جهاز المدرّب / instructor machine
$ mkdir -p /srv/remote.git && git init --bare /srv/remote.git
$ git remote add origin /srv/remote.git      # بدل رابط GitHub
$ git push -u origin main

تربط أجهزة الطلاب بالمجلد المشترك داخل الشبكة المحلية، فتكمل تدريبات الفروع والدمج والتعارضات كاملة بلا أي وصول للإنترنت، ثم تُزامن الرفع إلى GitHub لاحقاً عندما يعود. هذا أيضاً هو السكربت الذي وُلد منه هذا البرنامج، وقد استُخدم في توليد نماذج الحلول.

4 · إدارة الصف والمراجعة4 · Classroom & review management

أزواج المراجعة (Review pairings)

لا تدع الطلاب يختارون مراجعيهم بحرية تامة؛ الأصدقاء يتبادلون المدح. استخدم دوران (rotation): صفّ الطلاب، وكل طالب يراجع من يجلس بعيداً عنه. غيّر الاقتران في كل ورقة.

Rotate reviewers deliberately. Friends swap praise; rotation produces real feedback.

الجلسة نمط الاقتران عدد المراجعين لكل طلب سحب هدف المهارة
3 ثنائي (2 × 2) 1 كتابة أول مراجعة مكتوبة
4 ثلاثي حسب الأدوار (مطوّر + مختبر + كاتب) 1–2 مراجعة متخصصة
5 مراجعة مفتوحة (كل طالب على طلبين) 2 نقد تواريخ الدمج والنشر

سلّم تقييم جودة المراجعة (علّمه للطلاب قبل التطبيق)

المستوى الوصف مثال جيد من مشروعنا
5 نجوم ملاحظة محددة + سؤال + اقتراح تعديل + احترام «سطر 8: fullName اسم مختصر جداً، هل نضيف اسمك الكامل ليظهر صحيحاً في البطاقة؟»
3 نجوم ملاحظة صحيحة بلا اقتراح «حقل tags فارغ»
نجمة موافقة بلا تفصيل «ممتاز»
صفر نقد شخصي أو سخرية أو صمت —
قواعد التقدير التي أنصحك بإعلانها مسبقاًAnnounce these marking rules up front
  1. الأدلة هي الحكم: لا تحتسب مهمة بلا مخرجات أمر حقيقية من جهاز الطالب.
  2. المراجعة نصف الدرجة في الورقة 3، وربعها في 4 و5. من لا يراجع لا يُقيَّم كامل الدرجة.
  3. الدقة التقنية يُسامح عليها، والمخالفات الأمنية لا: نسيان أمر = مثال تعليمي؛ رفع token أو --force على فرع مشترك = خصم مباشر.
  4. الفهم العملي مقدَّم على الجمالية: ملف بـ 4 مسافات في الأخطاء البصرية لا يُخصم عليه؛ ملف بلا التحقق (node tests/validate-members.mjs) يُخصم عليه.
  5. حق إعادة المحاولة: لكل طالب إعادة تسليم واحدة خلال 48 ساعة على الأجزاء التي فشلت فقط، بشرط أن يرفق مخرجات جديدة.

قاعدة الدقيقتينThe two-minute rule

أي مشكلة لم تُحلّ مع الطالب خلال دقيقتين: سجّلها على السبورة في «طابور المشكلات»، وانتقل لغيره، ثم عالجها جماعياً في نهاية الجلسة. الطالب الذي يشغل المدرّب 15 دقيقة يحرم 15 طالباً آخرين من التوجيه — وهذا نمط شائع في ورش البرمجيات.

6 · أسئلة متوقعة من الطلاب (وأجوبتك النموذجية)6 · Expected questions
السؤال الجواب المختصر الذي تعطيه
هل يمكن الرجوع بعد commit خاطئ؟ نعم: قبل الرفع → git commit --amend أو reset --soft؛ بعد الرفع → git revert. والتزم كثيراً: كل التزام نقطة رجوع.
ما الفرق بين Git وGitHub بالضبط؟ Git برنامج يراقب التغييرات على جهازك. GitHub موقع يستضيف مستودعات Git ويتيح التعاون. لا يعمل أحدهما بدل الآخر.
لماذا لا أرفع مباشرة إلى main؟ لأن main هو النسخة التي يعتمد عليها الجميع؛ الفرع يحميك ويحمي الفريق حتى تُراجَع المساهمة.
هل أفقد عملي إن أخطأت في الأمر؟ لا، إلا في reset --hard وgit clean -fd وrestore على تعديل غير مُلتزم. وgit reflog يعيدك في معظم الحالات.
لماذا يظهر ملف members-bundle.js في كل تعديلي؟ لأنه ملف مُولَّد آلياً من البطاقات. لا تعدّله يدوياً، وسيُعاد توليده مع الفهرس.
هل تعارض الدمج خطأ يجب تفاديه؟ لا، التعارض رسالة طبيعية يقول فيها Git: «هنا تعديلان متضاربان، اختر أنت». مهارة حلّه هي محور الورقة 05.
كيف أعرف ما فعله زميلي؟ git log --oneline --graph --all ثم git diff ثم git blame. وطلبات السحب على GitHub هي أوضح عرض لحالة العمل.
هل يمكن إلغاء طلب سحب؟ نعم: Close pull request (يبقى التاريخ) أو استخدم git revert بعد الدمج. لا يوجد «حذف كامل» لسجل عام بل تصحيح معلن.
هل يجب أن يكون مستودعي عاماً؟ لا في مشاريع العمل الخاصة، لكن في هذه الورشة نحتاج العام لأن GitHub Pages على حساب مجاني يعمل مع مستودعات عامة.
كيف أستمر بعد الورشة؟ من أمثلة المهمة: أضف ميزة للموقع عبر فرع + طلب سحب، وشارك في مشروع مفتوح المصدر (first-contributions) لتمرين ممتع مماثل.

التدريب على مستودع جاهز يعلّم الأوامر. أما مشروع الفريق المخصّص فيعلّم العمل الجماعي المنظّم: أدواراً حقيقية، ميزانية مراجعة، ملكية ملفات، وتعاقدات على التاريخ — وهي المهارات التي يطلبها سوق العمل. لذلك: استخدم البدائل للتوسّع أو التعويض، وليس كبديل أساسي. وإن لم يوجد سوى مستودع جاهز، أضف عليه خطوة إضافية: اطلب من كل طالب إضافة ملف باسمه في مجلد students/ ليعيش تجربة «ملفي لا يتعارض مع ملفاتكم».

رسالة ختامية للمدرّبA closing note to the trainer

نجاح هذه الورشة لا يقاس بعدد الطلاب الذين يستخدمون git commit بسرعة، بل بعدد الطلاب الذين يتصرفون كزملاء في فريق بعد الورشة: يسألون قبل أن يرفعوا، يراجعون قبل أن يمدحوا، ويقرؤون مخرجات الأوامر قبل أن يخمّنوا. صمّم تدخّلك حول هذا الهدف، وستجد أن بقية المهارات التقنية تأتي تلقائياً معه.
